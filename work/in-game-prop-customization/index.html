CPD-Based Runtime Prop Customization

2026.07

Technical ArtMaterial ArtShader DevCustom Primitive DataPipeline / Tools

개발팀의 Runtime UI·상태 전달·저장·멀티플레이 동기화 기반 위에, 일반 프랍의 면별 Material Slot 할당을 전용 DCC Export Add-on으로 DCC의 두 번째 UV 채널인 UV02 (= Unreal TexCoord 1)의 Region 좌표에 기록하고 Export할 때 Material Slot 하나로 병합했습니다. Unreal Material에서 최대 4개 Surface Region을 CPD로 제어하는 Prefab(PFP) 콘텐츠 시스템과 Mesh Variant·Transform·동작 적용 규칙을 설계해 오픈베타 빌드에 적용했습니다.

Role
Prefab(PFP) Content System · DCC Export Add-on · UV02 / TexCoord 1 Region Mapping · CPD Surface Mapping & Index Budget · Mesh Variant Framework · Normalized Transform Mapping · Motion Method Design · Prop Art & Prefab Production
Project
VV World

Unreal Engine 5

Technical breakdown

개발팀이 제공한 Runtime UI에서 전달된 커스터마이징 값이, 제가 제작한 PFP의 CPD Surface·Mesh Variant·실제 Transform에 반영되는 결과입니다. Runtime UI와 네트워크 데이터 전달·동기화 시스템은 담당 범위에 포함되지 않습니다.

담당 범위

VV World의 Runtime UI, 커스터마이징 상태 데이터 전달, 저장 및 멀티플레이 동기화 기반은 개발팀에서 구축했습니다. 저는 프랍 아트 에셋과 Prefab(PFP)을 제작하고, 전달된 값을 CPD Surface, Mesh Variant, 실제 Transform과 선택적 WPO·Skeletal Mesh 동작으로 해석하는 콘텐츠 계층을 설계했습니다.

개발팀 제공 영역 — Runtime UI · 커스터마이징 상태 데이터 전달 · 저장 · 멀티플레이 동기화

담당 영역 — Prop Art · PFP 계층 · CPD Surface Mapping · Mesh Variant · Transform Mapping · 동작 방식 설계

목표와 제약

사용자가 다수의 소품을 배치·복제·저장하며 공간을 꾸미고, 프랍별 색상·재질 속성, Mesh Variant, 높이·각도와 동작 상태를 실시간으로 조절할 수 있어야 했습니다. 형태만 조금씩 다른 소품을 각각 Asset Browser에 등록하면 탐색과 Spawn을 반복해야 하고, 인스턴스별 표현을 위해 Material Instance를 계속 분화하면 콘텐츠 관리 구조도 복잡해집니다.

동일한 45° Trim 기반 Material을 사용하는 현대 공산품형 에셋이 많았기 때문에, Shared Material을 유지하면서 Primitive마다 다른 수치형 Surface 값을 전달할 방식이 필요했습니다. 동시에 개발팀의 공통 커스터마이징 입력 구조를 변경하지 않고, 서로 다른 프랍의 실제 가동 범위와 동작 방식을 콘텐츠 계층에서 해석해야 했습니다.

데이터 규격과 작동 방식

DCC Material Slots (Surface A–D / Emissive A–D / VC / Mtl_0)
→ Export Add-on
→ DCC UV02 Region Coordinates (= Unreal TexCoord 1) + One Material Slot · General Props

Provided Runtime UI
→ Customization State Data / Multiplayer Sync
→ Prefab Parameter Mapping
  ├→ Custom Primitive Data → Shared Parent Material
  │   + Unreal TexCoord 1 Region Decode → Surface / Emissive / VC / Mtl_0 Response
  ├→ Mesh Type Index → Static Mesh Array → Mesh Variant
  └→ Normalized 0–1 → PFP Min/Max Mapping → Component Transform

Surface 커스터마이징은 각 Region에서 Color RGB 3개와 Metallic·Smoothness 2개를 CPD로 전달하고, Material에서 Smoothness를 Roughness로 변환하도록 구성했습니다. 최대 Surface Region은 예외 없이 4개로 고정하고, Surface A–D에 총 20개의 CPD Index를 할당했습니다. 전체 CPD 인덱스 예산은 WPO Animation Speed를 포함한 Surface 외 제어값과 후속 기능 확장을 위한 여유 구간까지 고려해 설계했습니다. 2~3개 Region만 사용하는 PFP는 자식 Prefab BP에서 불필요한 UI 항목을 비활성화했습니다.

Material Slot은 DCC에서 파츠와 면의 역할을 지정하기 위한 제작 규칙이었습니다. DCC에서는 Surface A–D, Emissive A–D, VC, Mtl_0 Material Slot으로 각 면의 역할을 지정했습니다. 전용 Export Add-on은 면별 Slot 할당을 Region Selector 가이드에 맞춰 DCC UV02 (= Unreal TexCoord 1)의 Region 좌표에 기록하고, Export할 때 Material Slot 하나로 병합했습니다. Unreal의 공용 Material은 이 가이드 이미지를 샘플링하지 않고 TexCoord 1 범위를 직접 판별해 해당 표면 분기를 선택하며, Surface A–D는 각각 대응하는 CPD Index 구간을 읽습니다. 따라서 일반적인 프랍은 하나의 Material Slot만 사용했습니다.

Surface A–D는 일반 표면 커스터마이징 영역, Emissive A–D는 발광 표면 영역으로 사용했습니다. VC는 미리 지정된 Vertex Color와 일반 표면 처리를 함께 사용하는 영역이며, Mtl_0는 사전에 정의한 일반 Metallic 재질 0번입니다. 나머지 Selector 영역은 필요에 따라 새로운 표면 유형이나 Preset을 추가·개조할 수 있도록 남겨 두었습니다.

PFP 계층과 Mesh Variant

모든 프랍이 사용하는 Surface Region 처리만 최상위 Parent에 두고, Mesh Type과 Transform 기능은 카테고리별 Child Parent에서 처리했습니다. 실제 PFP는 적합한 Parent를 상속해 Mesh Array, Pivot·Axis와 Min·Max 범위 등 에셋별 값만 설정하도록 구성했습니다.

스툴의 높이, 소파·벤치의 좌석 수, Pillar 형태, 화분에 심긴 식물의 수처럼 관련된 Static Mesh를 하나의 PFP Family로 묶었습니다. 사용자는 색상과 재질을 설정한 PFP를 복제한 뒤 Mesh Type만 변경해 동일한 스타일의 Variation을 구성할 수 있습니다.

Transform과 동작 방식

높이와 각도는 UI에서 0~1의 정규화된 값으로 전달받고, PFP의 Mapping Function에서 프랍별 Min·Max 범위로 변환해 실제 Component Transform에 적용했습니다. 개발팀의 공통 UI·입력 데이터 전달 구조는 에셋별 실제 단위를 알 필요가 없고, 콘텐츠 제작자가 각 프랍의 Pivot·Axis와 허용 범위를 결정하도록 역할을 분리했습니다.

WPO는 단순 반복 동작이면서 멀티플레이 동기화가 필요하지 않고, Bounds·Virtual Shadow Map·캐릭터 정합성 위험이 낮은 경우에만 사용했습니다. 마이크 스탠드와 Boom Arm처럼 캐릭터와 밀접하고 사용자 설정을 동기화해야 하는 소품은 실제 Component Transform을, 관절과 복합 애니메이션 상태가 필요한 동물형 프랍은 Skeletal Mesh를 사용했습니다.

  • DCC Export Add-on과 Surface A–D·Emissive A–D·VC·Mtl_0 Region Selector 규격 구성

결과와 한계

스툴, 소파, 화분, 의자, 마이크 스탠드처럼 구조가 다른 프랍을 개발팀의 동일한 커스터마이징 입력 체계에 연결하고, VV World 오픈베타 빌드에 적용했습니다. 다만 오픈베타 직후 운영이 중단돼 실제 사용 빈도나 사용자 편의성은 충분히 검증하지 못했습니다.

오픈베타 적용 버전에서는 일반 프랍의 면별 Material Slot 할당을 Export Add-on으로 DCC UV02 Region 좌표에 기록하고, Export할 때 Material Slot 하나로 병합했습니다. Unreal Material은 동일한 채널을 TexCoord 1로 읽었습니다. 적용된 Selector는 Surface A–D, Emissive A–D, VC, Mtl_0를 제공했으며, 남은 영역에는 필요에 따라 새로운 표면 유형이나 Preset을 확장할 수 있도록 설계했습니다. 프로젝트 종료로 후속 Region 확장과 장기 사용자 검증은 진행하지 못했습니다.
