파편화된 Parent Material의 공통 처리 구조를 Function으로 통합

Legacy Material Expansion & Shared Function Library

2021–2023

Pipeline / ToolsMaterial ArtShader DevOptimization

M_Basic·M_Basic_Detailed 등 여러 Parent Material에 분산돼 있던 공통 처리를 UE4 MF_Basic으로 통합하고, Color Adjustment·Detail Normal·Vertex Color·UV Atlas와 Utility 기능을 조합 가능한 Material Function 구조로 확장했습니다. UE5 전환 시 MF_Basic_Material로 전면 리팩토링해 Material Attributes와 개별 Channel·Mask·UV를 함께 제공하고, Parameter 명칭·Category·Static Switch와 문서화·운영 기준까지 공용화했습니다.

Technical breakdown

파라미터 명칭·정렬·카테고리와 기능별 ON/OFF 규칙을 통일해, 엔진 숙련도가 서로 다른 작업자도 Material Instance에서 필요한 기능을 찾고 조절할 수 있도록 정리했습니다.

문제·제약

기존 사내 재질 기반은 M_Basic·M_Basic_Detailed·M_Basic_*** 등 여러 Parent Material에 Texture·Tiling과 유사 Parameter가 분산돼 있었습니다. 공통 기능을 수정하거나 오류를 대응할 때 Parent마다 같은 로직을 반복 확인·수정해야 했고, 프로젝트와 작업자에 따라 Parameter 탐색·설정 기준도 달라졌습니다.

일반 Surface와 별도 Parent·Unique Material이 같은 기초 처리를 필요로 했지만, 각 Material에 공통 로직을 복제하면 변경 경로와 영향 범위가 다시 분산되는 문제가 있었습니다.

UE4에서 UE5로의 구조 진화

UE4에서는 Texture Sample·Tiling 등 반복되는 기초 처리를 여러 Parent가 재사용할 수 있도록 MF_Basic으로 통합했습니다. Legacy Parent에 없던 Color Adjustment·Detail Normal·Vertex Color·UV Atlas와 Utility 기능은 조합 가능한 Material Function으로 추가해 공통 기반과 기능별 확장 로직을 분리했습니다.

UE5 전환 시에는 기존 MF_Basic을 MF_Basic_Material로 전면 리팩토링했습니다. 누적된 기능을 다시 정리하고 Parameter 명칭·Category·Sort Priority·Static Switch를 공용 규칙으로 재설계해, 일반 Surface와 특수 Material이 같은 기초 처리 구조에서 시작하도록 구성했습니다.

확장 Interface

MF_Basic_Material은 완성된 Material Attributes뿐 아니라 개별 Channel·Mask·처리된 UV도 함께 출력합니다. 일반 Parent는 공통 출력을 그대로 사용하고, Unique Material은 Get/Set Attributes와 Utility Function을 후단에 조합해 필요한 기능만 확장하도록 했습니다.

공통 Surface 로직을 복제하지 않고도 각 Material의 특수 기능을 추가할 수 있어, 일반 Parent와 Unique Material이 동일한 변경 지점을 공유합니다.

작업자용 Parameter 규칙

Material Instance에서 기능을 찾고 설정하는 순서가 프로젝트와 작업자에 따라 달라지지 않도록 Parameter 명칭·Category·Sort Priority를 기능 순서에 맞춰 재구성했습니다. 필요한 기능만 Static Switch로 선택하도록 정리해 Environment·VFX·LookDev가 같은 Interface와 ON/OFF 규칙을 사용하도록 했습니다.

프로젝트 이관과 공통 변경 관리

다수 Parent·Unique Material이 MF_Basic_Material을 공통으로 참조하도록 구성해 기능 수정과 오류 대응의 변경 지점을 중앙 Function에 집중했습니다. 프로젝트 간 에셋 이관 시 누락되거나 교체가 필요한 Parent Material을 추적하고, 공용 Function 기반 Parent로 대체했습니다.

공통 Function에서 변경 지점과 참조 경로를 확인할 수 있어 Parent·Unique Material의 영향 범위를 따라가며 수정할 수 있도록 운영했습니다.

문서화와 기술지원

Texture 압축 방식·Parameter 사용 규칙·기능별 ON/OFF 기준을 화면 예시와 함께 Notion 가이드로 정리했습니다. Environment·VFX·LookDev가 같은 설정 방식을 사용할 수 있도록 문서를 전파하고, 공통 오류의 재현·수정 절차도 기록해 반복 기술지원에 활용했습니다.

검증·성과

전환 기간에는 Legacy Parent와 공존시키되 신규 사용은 중단하고, 재직 기간 동안 사내 프로젝트의 일반 Surface Material 제작을 공통 Function 기반으로 운영했습니다. 일반 Parent와 Unique Material이 같은 기초 처리와 작업자용 Interface를 재사용하면서, Parent마다 반복하던 공통 수정 지점을 MF_Basic_Material 한곳으로 통합했습니다.

공용 Function 구조를 기준으로 프로젝트 이관 시 Parent 참조 문제를 추적하고, 기능 수정·오류 대응·작업자 지원을 동일한 운영 기준으로 연결했습니다.
